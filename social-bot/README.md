# Бот публикаций в Instagram и Threads

Публикует посты в `@salammotion` (Instagram и Threads) по очереди `queue.json`. Запускается сам каждый час через GitHub Actions
(`.github/workflows/social-post.yml`).

## Правила оформления роликов (от автора)

Применять к каждому ролику, в том числе в автоматическом монтаже:

- **Эффекты всегда мягкие**: тихо (не громче звука ролика), без резких верхов, с плавным хвостом.
- **Не перегружать**: звук только там, где у него есть смысл; без озвучки каждого движения, без ударов и райзеров по умолчанию.
- **Одна музыка за раз**: если у сгенерированного ролика свой звук, под ним ничего своего не играет.
- **Без синтезированного звука**: только файлы из пака автора (приватный репозиторий `artega909-del/salam-assets`).
- **Текст без дублей**: одна мысль на экран, не больше ~3 слов в секунду чтения.
- **Логотип и ссылка `salammotion.com` обязательно** (финальная карточка; в интерфейсе — шапкой).
- Всё важное — вне зон интерфейса Reels: сверху ниже 280 px, снизу выше 1560 px, правая колонка кнопок свободна.

## Секреты

Хранятся **только** в GitHub: Settings → Secrets and variables → Actions.

| Имя | Что это |
|---|---|
| `INSTAGRAM_ACCESS_TOKEN` | токен системного пользователя Meta (без срока действия) |
| `INSTAGRAM_ACCOUNT_ID` | ID Instagram-аккаунта из Business Settings |
| `THREADS_ACCESS_TOKEN` | токен Threads (необязательный; без него записи для Threads ждут) |

Токен нельзя вставлять в файлы репозитория (сайт публичный), в чат и на скриншоты. Если он где-то засветился: Business Settings →
Системные пользователи → `salam-bot` → «Отозвать маркеры», затем создать новый.

## Как добавить пост

Отредактируйте `social-bot/queue.json`, добавив запись в `posts`:

```json
{
  "id": "salam-002",
  "brand": "salam",
  "platform": "instagram",
  "type": "REELS",
  "media": "assets/salam-002.mp4",
  "caption": "Текст подписи #хештег",
  "publish_at": "2026-12-03T09:00:00Z",
  "status": "scheduled"
}
```

- `type`: `REELS` (видео `.mp4`/`.mov`, лучше 9:16), `IMAGE` (JPEG) или `CAROUSEL` (карусель: `media` — список из 2–10 JPEG, лучше 1080×1350), или `STORY` (история: JPEG или видео 9:16, 1080×1920; подписи у историй нет).
- `media`: путь к файлу внутри репозитория (например `assets/…`; файл должен быть загружен в репозиторий и опубликован
  на GitHub Pages) или готовая ссылка `https://…`.
- `publish_at`: время UTC (`Z` на конце). 09:00 по Ашхабаду (UTC+5) — это `04:00:00Z`.
- `status`: `draft` — черновик, бот не трогает; `scheduled` — опубликовать, когда наступит время.
- Подпись до 2200 символов, до 30 хештегов.
- `cover_ms` (необязательно, только для REELS): кадр-обложка, миллисекунды от начала видео, например `0` или `1500`.
- `repeat: true` (необязательно): разрешить пост с подписью, которая уже есть в последних 25 постах аккаунта.

Статусы, которые проставляет бот: `published` (с `media_id` и `permalink`), `failed` (причина в `error`),
`missed` (время прошло более 48 часов назад — назначьте новое и верните `scheduled`).
Бот не повторяет неудачные посты сам, чтобы не опубликовать дважды.
Защита от двойной публикации: перед публикацией бот сверяет подпись с последними 25 постами аккаунта. Если такой пост
уже есть (прошлый запуск опубликовал, но не успел сохранить статус), запись помечается `published` с пометкой в `note`.
Поэтому подписи разных постов должны отличаться (или ставьте `repeat: true`).

## Threads

Запись для Threads отличается полем `"platform": "threads"`:

```json
{
  "id": "th-001",
  "brand": "salam",
  "platform": "threads",
  "type": "TEXT",
  "caption": "Совет дня: одно действие на кадр. Не сюжет целиком, а один понятный момент.",
  "link": "https://salammotion.com",
  "publish_at": "2026-12-03T09:00:00Z",
  "status": "scheduled"
}
```

- `type`: `TEXT` (только текст), `IMAGE` (JPEG или PNG), `VIDEO` (`.mp4`/`.mov`), `CAROUSEL` (`media` — список из 2–20 картинок и видео).
- `caption` — текст поста, до 500 символов. В Threads работает один тег на пост.
- `link` (необязательно, только у `TEXT`) — ссылка, которая покажется карточкой с превью.
- Токен Threads живёт 60 дней. Бот сам продлевает его при публикациях, когда остаётся меньше 45 дней, и пишет
  предупреждение в лог, если остаётся меньше 10 дней и продлить не удалось. Срок виден в режиме `check`.
- Как получить токен: приложение Meta → сценарий «Доступ к Threads API» → добавить свой аккаунт Threads тестировщиком,
  принять приглашение в настройках Threads → сгенерировать токен с разрешениями `threads_basic` и
  `threads_content_publish` → сохранить в секрет `THREADS_ACCESS_TOKEN`.

## Второй аккаунт (англоязычный)

Записи для второго аккаунта отличаются полем `"account": "en"` (для Instagram и для Threads). Без поля — основной аккаунт.

| Секрет | Что это |
|---|---|
| `INSTAGRAM_ACCOUNT_ID_EN` | ID англоязычного Instagram-аккаунта (назначить его системному пользователю salam-bot) |
| `THREADS_ACCESS_TOKEN_EN` | токен Threads этого аккаунта (аккаунт добавить тестировщиком Threads в приложении) |
| `INSTAGRAM_ACCESS_TOKEN_EN` | если аккаунт нельзя добавить в портфолио: токен «входа через Instagram» (начинается с IG) из приложения → Instagram API → «Сгенерировать маркер». Живёт 60 дней, бот продлевает его при каждой публикации |

Пока секретов нет, записи `en` ждут, основной аккаунт публикуется как обычно. Режим `check` проверяет оба аккаунта.

## YouTube Shorts

Запись: `"platform": "youtube"`, `"type": "SHORT"`, `media` — вертикальное видео .mp4 до 3 минут, `title` — заголовок
(до 100 символов), `caption` — описание, `tags` — список слов (необязательно), `account` — как у Instagram (без поля —
Salam Motion, `en` — Artega). Бот ставит отметку «сгенерировано ИИ» (`ai: false` — снять), доступ `public`
(`privacy` — `unlisted` или `private`) и проверяет повтор по заголовку среди 25 последних видео канала.

| Секрет | Что это |
|---|---|
| `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET` | OAuth-клиент проекта Google Cloud с включённым YouTube Data API v3 |
| `YOUTUBE_REFRESH_TOKEN` | постоянный ключ канала Salam Motion (OAuth Playground, права youtube.upload и youtube.readonly) |
| `YOUTUBE_REFRESH_TOKEN_EN` | то же для канала Artega |

Экран согласия OAuth должен быть в рабочем режиме: в тестовом ключ перестаёт действовать через 7 дней.
Если YouTube оставит видео приватным (API-проект без проверки YouTube), бот запишет это в `note`.

## Проверка

GitHub → Actions → «Instagram — публикация по очереди» → Run workflow:

- `check` — проверяет, что токен и аккаунт работают, ничего не публикует;
- `dry-run` — показывает, что вышло бы в эфир сейчас;
- `publish` — публикует то, что пора.

Локально без интернета: `node social-bot/test.mjs` (подменяет Instagram API).

## Важно знать

- Все файлы репозитория публичны на GitHub Pages, включая `queue.json` (подписи черновиков видны всем).
- Бот просыпается раз в час (в :17 по UTC), поэтому пост выходит в течение часа после `publish_at`; GitHub иногда задерживает расписание ещё на несколько минут.
- Расписание GitHub работает только на основной ветке (`main`). Бот коммитит обновлённые статусы очереди в `queue.json`.
- Если репозиторий 60 дней без активности, GitHub отключает расписание в публичных репозиториях; коммиты бота считаются активностью.
- Публикация через API ограничена Instagram (около 100 постов в сутки); бот публикует не больше 6 записей за запуск (оба аккаунта вместе).

## Оформление уже загруженных видео YouTube

Workflow «YouTube — оформление загруженных видео» (Actions → Run workflow):

- `report` — собирает список видео канала и их превью. Отчёт может содержать видео по ссылке и приватные,
  поэтому он шифруется открытым ключом `social-bot/report-pub.pem` и сохраняется в рабочую ветку в виде шифра;
  закрытый ключ в репозиторий не попадает.
- `apply` — применяет правки из `social-bot/yt-edits.json` (название, описание, теги, категория, язык, превью,
  доступ). Применённые записи получают отметку `applied` и повторно не трогаются.

Для `apply` нужен refresh token с доступом `youtube.force-ssl` (для загрузки Shorts — ещё `youtube.upload`).

## TikTok (черновики во «Входящие»)

Пока приложение не прошло аудит TikTok, публиковать сразу в открытый доступ нельзя, поэтому бот отправляет ролик
черновиком: автору приходит уведомление в TikTok, он вставляет подпись (поле `caption` записи), при желании добавляет
звук и публикует. Запись: `"platform": "tiktok", "type": "DRAFT", "media": "assets/….mp4"`.

Подключение:
1. developers.tiktok.com → Manage apps → создать приложение (Web). Terms of Service URL — `https://artega909-del.github.io/terms.html`,
   Privacy Policy URL — `https://artega909-del.github.io/privacy.html`.
2. Добавить продукты Login Kit (Redirect URI `https://artega909-del.github.io/tiktok-callback.html`) и Content Posting API
   (без Direct Post), права `user.info.basic` и `video.upload`.
3. В GitHub Secrets: `TIKTOK_CLIENT_KEY` и `TIKTOK_CLIENT_SECRET` (раздел Credentials приложения).
4. Открыть `tiktok-callback.html`, ввести client key, войти в TikTok, скопировать код и запустить workflow
   «TikTok — подключение» с этим кодом.

Ключ обновления TikTok живёт 180 дней и меняется при каждом обновлении, поэтому хранится не в секретах, а в
`social-bot/tiktok-token.json` (для en — `tiktok-token-en.json`) в зашифрованном виде; бот сам перезаписывает файл.
Если сменить `TIKTOK_CLIENT_SECRET`, файл перестанет читаться — подключите TikTok заново.
